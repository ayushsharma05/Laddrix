# Laddrix v1.0.0: core v1

**Status:** release candidate `1.0.0-rc.1`. It becomes `v1.0.0` when Ayush has run the live steps of the [go-live checklist](../runbooks/go-live.md) and recorded his v1 acceptance on #240. Only then is the tag made.

Laddrix v1 is a trading platform for NSE and BSE through Zerodha Kite Connect. It has a paper broker that fills against live (or simulated, or recorded) prices, a widget workspace in the browser and a desktop app. It runs on one server in Mumbai with a static IP.

## What is in v1

| Area | What you get |
|---|---|
| **Prices** | Kite login from the screen each morning; the instrument list; live ticks with depth; recording every tick, with each day's instrument list |
| **Orders** | Market, limit, SL, SL-M; DAY and IOC; CNC, MIS, NRML. Modify, cancel, baskets. The order spec comes from the server, so the screens hard-code no market rules |
| **Safety** | The risk gate (lots, price band, value, worst-case position, daily loss, open orders, double clicks); the throttle (8/s, 350/min, 4,500/day); STOP per account and firm; recovery after a restart; the broker check; UNPROTECTED and stale-price warnings |
| **Paper broker** | Fills against market depth, with queue position, latency and Kite-like rejects |
| **Positions and money** | P&L from fills; funds, holdings and the tradebook; charges; pre-trade margin; MTM limits; the square-off assistant; end-of-day reports |
| **Algos** | Slicer, TWAP, VWAP, POV, Iceberg, Spreader; trailing stop, OCO, Bracket (held by Laddrix); GTT orders held by the broker |
| **Options** | Pricing and greeks, the option chain, a strategy builder |
| **Research** | Replay a recorded day into paper trading; backtests; imported candles |
| **Charts and alerts** | Candle charts; market alerts with webhooks; time and sales, depth, movers |
| **Screens** | A widget workspace: widgets open, close and resize anywhere, with pop-outs to other monitors, saved per user. Ladder, ticket, order book, positions, audit trail, messages and the rest. Keyboard shortcuts and themes (dark, light, colour-blind safe), saved per user |
| **Admin** | Users and roles (admin, trader, risk), broker accounts, per-account limits, first-login password change, two-factor login |
| **Operations** | Docker Compose with Caddy (HTTPS); daily backups of all state and a checked restore; runbooks; a go-live checklist; this release process |

The full history is in `context/conversation-log.md`, and each part's design is in `docs/design/`.

## Data migrations

- **None to run by hand.** At start, `users.db` gains any column a newer version needs (`_ADDED` in `server/users.py`); nothing is removed or rewritten. `events.db` only ever gains rows.
- **Going back to an older version** works with the data as it is: older code ignores columns it doesn't know. If a release notes a migration that can't run backwards, roll back with that release's pre-deploy backup ([release.md](../runbooks/release.md) § Rollback).

## Known limits

- **Phone screens are after v1 (#283).** The screens are built for a desktop browser.
- **Stops held by Laddrix work only while the server runs.** This covers the trailing stop, OCO and bracket. A restart shows **UNPROTECTED** for each affected position. A broker GTT survives our outages.
- **Paper orders don't survive a restart.** Positions and P&L do; working paper orders are closed, with the reason given.
- **Backtests look contracts up in today's instrument list,** so an expired contract's day can be replayed but not yet backtested (noted for hardening, #257).
- **Live evidence comes from Ayush.** The go-live checklist's live boxes are his to run. The automated evidence is paper, and is labelled as paper.
- **The hardening findings (#257) come after v1.** That includes #258–#277, security #279 and the data-rights decision #278.
